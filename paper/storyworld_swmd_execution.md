# SRG-04: Executable SWMD compiler and TypeScript editor integration

2026-11-25. Evidence: 29 executed finite conformance checks, source-pinned TSUN migration and exhaustive replay in an isolated ECMAScript runtime. No model calls, no Lean claim, no TypeScript application build or browser UI execution.

## Delivery and scope

The upstream sweepweave-ts branch creation returned HTTP 403 (integration cannot create refs). Accordingly all files are delivered in EvalMath under integrations/sweepweave-ts/srg04/, with an opt-in installer targeting the reviewed TypeScript Play tab. The editor repository is unchanged. The signed runtime is intentionally independent of the incomplete legacy TS path: at reviewed sweepweave-ts revision 52e8b446592639eb3a63f7824fc6edc5af9be7f1, Reaction.calculate_desirability returns zero, Actor's BNumber read/write methods are stubs, and ScriptManager's legacy parser lacks several arithmetic operators. No equivalence to that legacy runtime is asserted.

SWMD-SRG/1 is an executable **direct-routing subset**, not a lossless converter for every historical world. It supports full owner/property/subject/second-subject keys, signed numeric state, exact source decimal literals parsed to finite binary64, explicit comparator directions, numeric/boolean expression type checks, ordered assignments (including repeated writes), explicit reaction gates and deterministic first/last ties, initial state, time windows, encounter guards, visibility and performability. Intermediates can exceed the BNumber domain; assigned values must lie in [-1,1], with explicit CLAMP available. NUDGE uses signed asymptotic semantics, BLEND normalizes a signed weight. Unsupported expressions, missing coordinates, malformed or ambiguous records, undeclared destinations and legacy minified inputs fail closed. Direct destination guards are checked after effects. No silent wild/spool fallback. This subset does not yet represent stochastic reactions, dynamic spool scheduling, event prerequisites, full encounter/reaction prose, or arbitrary metadata. The fixture converter retains option prose and mechanical fields, not complete narrative content. It is not a drop-in replacement for the editor's JSON editing workflow.

The syntax is demonstrated in fixtures/council.swmd.md and fixtures/tsun01b.swmd.srg.md. It uses a header, id/title/start/tie, VAR declarations with explicit public/hidden visibility, ENC with time and acceptability, OPT with visibility and performability, and ORX lines with destination, O:, E:, D:, G:. Player observation contains only the declared public values, encounter ID, turn and legal action menu. Menu and narrative can still intentionally communicate evidence about hidden state. No verifier-only reward, hidden state or forced alternate branches are included. Author view and privileged audit export are not security isolation for a hostile local user with access to source.

## Counterfactual export

Given an immutable compiled world and a validated pre-state, enumerate every option passing both gates. Evaluate reaction desirability and eligibility, preserve the maximizing tie set and the selected ID, then apply each eligible reaction on a separate copy. Each branch records route, destination-guard status, ordered before/after writes, full successor and sum of squared coordinate displacement. The selected branch is the actual deterministic successor; other eligible branches are forced interventions, not actions available to the player. A legal menu entry with no eligible reaction or a blocked destination is explicitly flagged; an invalid expression/effect aborts the audit. A bad forced branch can therefore fail an otherwise playable action in this fail-closed authoring runtime.

The TypeScript panel uses the same functions for playing and for exporting audit packets. History records the chosen action/reaction and actual successor as well as alternatives. Full audit source and hidden state are labelled verifier-only. Use that packet only in trusted author/verification workflows; strip future outcomes and full state before model prompting. The installer previews its target by default, verifies package identity and the pinned Play tab Git blob, refuses to overwrite an existing SRG directory, and only changes files with --apply. Browser and TypeScript compile checks are pending.
