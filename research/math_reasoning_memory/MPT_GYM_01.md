# MPT-GYM-01: Development-only Lean reasoning-memory pilot

Status: proposed development protocol. No calibration sample or confirmation split has been opened. Finite suite: EM-MPT-01--06, see paper/math_reasoning_memory.md. The two external publications motivate the design; their reported aggregate losses are not transferable thresholds.

## Scientific question

At a fixed checkpoint and total charged compute, can a learned compact controller preserve a competent symbolic history-aware controller's benefit over a clock/progress-only controller? Separately estimate whether changing checkpoint loss shifts root closure under identical scaffold and cost. Test persistent certificates and strategy history separately. MPT-03's 2.34-point synthetic gain is below the provisional 5-point practical floor.

## Stage D0: Freeze data and verifier

Use existing Lean repair gym tooling in DataGoblin/LoopedTransformers after checking their current API and source commit. Construct 64 independent generator worlds for development; include depth 2,4,8,16 and disjoint theorem-family templates, with graph-matched variants clustered within roots. The 64 worlds may not be enough for the scientific effect; use them to diagnose signal and estimate variance only. Reserve at least 59 independent sham worlds to estimate a 95th percentile envelope at 95% confidence via a sample maximum; 64 development worlds can serve if their sham outcomes are independently generated across roots and not selected. Keep confirmation inaccessible. Generate proof environments strictly before target declarations, refuse imports of target/descendant theorems, audit axioms and verify proof dependencies. Include self-citation and shuffled/misleading lemma sentinel cases. Reject any leakage before scoring. Record generator version, root ID, theorem family, pre-declaration environment hash, target hash, tactic action set, dependency graph provenance and all verifier receipts. A privileged oracle graph is a separate ceiling.

## Stage D1: Compare controllers

Within every development root, compare (a) strong symbolic budgeted search with verified persistence and full strategy history, (b) the same with history reset or shuffled while retaining identical proof state, graph and budget, (c) clock/progress-only, (d) finite-state compressed or quantized controller, (e) learned recurrent controller, (f) static quota comparator, (g) graph-oracle ceiling. Freeze primary comparison (d or e chosen on development) versus the matched history reset at fixed total charged compute, alongside (a) as a strong symbolic competitor. Use the same checkpoint, tactic availability, verifier, context access and randomization contract for paired arms. Compare no-persistence versus persistence separately with a graph-matched control and full resource accounting; do not change two mechanisms in the primary contrast. Predeclare budgets as measured wall-clock/GPU compute ceilings and record tokens, FLOPs estimate, CPU verifier time/calls, peak memory, retrieval and ledger overhead, compiled table bytes, mutable state bits, failed/rejected attempts, context tokens and terminal closure. No free oracle input; all extra storage and compute must be counted. Record seeds and model hashes. Run CPU symbolic fixture first; use existing compact model checkpoints only after confirming availability. No H100 request or spend authorized by this note.

## Stage D2: Loss and calibration

Use one held-out witness corpus and tokenizer across checkpoints for negative log likelihood; compare only commensurate units and report calibration by theorem family. Log full ordered actions, outcomes and budget. Fit latent or observable conditional-history models only on development data. For MPT-06, each calibration cell must have independent fixed-design roots with the same declared conditional history/action sampling law as deployment; if conditional histories are too rare or a sampling intervention shifts their distribution, report an uncalibrated [0,1] bound. Do not confuse within-world attempts with independent samples. Freeze controller family and cell alpha allocations before collecting calibration outcomes. Evaluate calibration and envelope coverage on a separate validation split. Compare actual closure curves with envelopes; no claimed phase transition unless a predeclared threshold model defeats a smooth alternative under held-out checkpoint and theorem-family testing.

## Stage D3: Preflight gate

Primary unit is generator world; scored observations are clustered within it. Primary contrast is paired root closure gain, provisional scientific floor 0.05 absolute probability. Record n_units and n_cases separately. Report the physical intervention (state reset/shuffle or fixed bits), matched sham floor and confidence source, actual planned comparison family (including screened variants), observed development effect and dispersion. Run EvalMath's skills/evalmath-mechinterp-power/scripts/preflight.py --pilot pilot.json --strict using actual independent development summaries and the current script's schema. If the effect is below the scientific/sham resolution floor, or estimated independent-root count is insufficient, label PILOT_ONLY/REDESIGN; no claim of equivalence from null results. Freeze a single candidate, budget, alpha family, seed plan, equivalence/noninferiority margin if needed, primary endpoint, exact stopping rules and confirmation root count only after this gate. Allocate fresh disjoint families for confirmation. A five-point floor is provisional; no power estimate or sample size for confirmation is asserted without development data. Archive unfavorable results as well.

## Stage C: Prospective confirmation

Run once on the sealed independent roots at the frozen resource ceiling. Use EvalMath FSI-01 root-level paired exact inference where binary independent roots apply, cluster-level inference otherwise, and correct the full registered comparison family. Report all outcomes, confidence intervals, prediction calibration, actual resource use and source hashes. Pass only if the registered scientific effect, uncertainty and matched-sham separation gates hold; use a registered noninferiority margin to claim compression preserves performance. A claim of learned reasoning mechanism needs causal history intervention and comparison with symbolic history-aware policy, beyond high solve rate. Evidence levels: exact synthetic mathematics, development diagnostic, prospective empirical, and formal Lean are separate.
