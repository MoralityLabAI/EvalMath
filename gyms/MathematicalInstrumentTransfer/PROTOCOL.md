# MIT-01B proposed pilot (unregistered, no runs)

Primary question: does a source-derived instrument increase independently verified target closure at equal total budget on unseen generator families, and can a calibrated selector avoid inapplicable mappings?

Unit: one independently generated source-target theorem root; all mutations, attempts, seeds and arms are paired observations. Family-level generalization requires whole families held out, not merely renamed lemmas. Start with a small development set from finite LP duality, graph cycle invariants, modular arithmetic and polynomial positivity; extend only after checking generators and running the repository power preflight. The previously proposed 256 roots across eight families is a planning ceiling, not a powered sample size. A candidate absolute closure gain of 10 percentage points must exceed matched-sham variation and measurement resolution before confirmation. Do not open a sealed split until a development pilot exists and the command python skills/evalmath-mechinterp-power/scripts/preflight.py --pilot pilot.json --strict passes for the chosen effect and root accounting. Use FSI-01 for paired inference; report family clusters separately and restrict claims accordingly.

Freeze source theorem and target statement before model runs. Build target pairs with a valid mapping and a matched near-miss (one required hypothesis fails), verified by an independent checker or explicit countermodel. The source artifact may reveal a method but must not contain the target proof, answer, target theorem name, or target-correlated identifiers. Pin Lean environment before the declaration under proof; block target self-citation, added axioms, sorry, and environment leakage. Use checker logs and explicit prerequisite witnesses to score applicability. For false targets, evaluate rejection/counterexample separately from closure of true targets.

Paired arms: unaided; full source proof; abstract instrument with prerequisites; length- and format-matched inapplicable instrument; oracle instrument with applicability mapping. Add shuffled irrelevant source as token-matched sham. Randomize order independently and use fresh model state, identical initial theorem context and a frozen budget schedule. Charge source reading, mapping, queries, generated and rejected tokens, tool calls, retries and verification time; report token, verifier-call and wall-clock budgets separately, with a predeclared primary budget. Include a blind shortlist policy and heuristic selector when testing a learned controller. Record failures and abstentions.

Primary outcome: target proof accepted under the pinned statement and axiom audit within budget, paired instrument versus matched sham. Secondary: applicability classification including false accepts; closure versus unaided; cost per closure; source-to-target transfer versus source recall; budget curves; calibration (Brier and reliability by held-out family); controller overhead. Preregister comparisons, inference and stop gates after development only. Neural intervention evidence is a separate project; no TRM, Inky or Bonsai runs are authorized by this draft alone.

Receipt schema: root_id, source_family, target_family, generator_seed, source_hash, target_statement_hash, required_hypotheses, applicability_gold, arm, prompt_hash, model/checkpoint, total_budget, acquired_tokens, generated_tokens, verifier_calls, wall_ms, selected_instrument, predicted_applicability, proof_hash, proof_verified, axiom_audit, stop_reason. Retain independent pilot and sealed manifest hashes and every failed attempt.
